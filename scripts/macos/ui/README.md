# UI scripts

The app can drive itself, so the real window can be checked without Accessibility permission
or synthetic system events. A script is a JSON array of steps; the app runs them on its main
run loop through the same paths a person would use (key events into the window, menu actions
through the responder chain, settings), writes PNG snapshots and `log.json`, and quits with a
non-zero status if an assertion failed.

```sh
scripts/macos/ui-script.sh scripts/macos/ui/smoke.json          # debug bundle -> build/ui/smoke/
RELEASE=1 scripts/macos/ui-script.sh scripts/macos/ui/big.json  # release build (timings)
SKIP_BUILD=1 scripts/macos/ui-script.sh my.json out/dir        # reuse build/Markdown.app
UI_BUILD=/tmp/ui scripts/macos/ui-script.sh my.json             # build and run /tmp/ui/Markdown.app instead
```

The harness is compiled into debug builds, and into release builds only with
`scripts/macos/bundle.sh --release --ui-script` (`-DUI_SCRIPT`). It runs only when the app is
launched with `--ui-script <file>` (`--ui-out <dir>`, `--ui-root <dir>` for relative paths). It
uses its own defaults suite (never the user's settings) and opens copies of the files it is
given. Set `UI_SCRIPT_TRACE=1` to log every step as it starts.

Every window the app shows under a script ignores the real mouse (`ignoresMouseEvents`), so a click of
yours in a harness window cannot mix with the script's own events (a scripted click and yours made a
double-click that zoomed the window); document and Settings windows open at the top-left corner of the
screen, which marks them as the harness's. The steps that need real mouse events still get them: they
are posted to the app's queue or sent to the window, which never goes through the window server's
hit-testing, the only thing the flag changes (`ClickHitTestTests` checks it). The app takes activation
(and your keyboard) only for a script that has a step needing it (`click`, `drag`, `dividerDrag`,
`liveResize`, `doubleClickTitlebar`, `fullscreen`, `codeBadge`), and only at launch:
since macOS 14 an app in the background is refused activation later, and with the screen locked it is
refused at launch too, so those steps fail (logged with `"active": false`) when the session is locked
or another app is made active during the run. `{"assert": {"harnessWindows": true}}` checks the flag on
every visible window and the corner (`"atCorner": false` skips the corner).

Any Objective-C exception stops the script at once: it is logged with the stack of the throw
(stderr), recorded in `log.json`, and the app exits with status 3 (no crash report, no dialog).
`UI_SCRIPT_EXCEPTIONS=log` only logs them. The runner holds an activity assertion (no App Nap, no idle sleep of the system or the display, no automatic or sudden termination) for the whole run; `UI_SCRIPT_ALLOW_NAP=1` removes it. Without it a script that runs for minutes with no one at the machine is throttled by macOS to a quarter of the speed after about a minute, which looks exactly like the app slowing down late in a long session (it was the cause of that report). Undo and redo are `{"undo": true}` and `{"redo": true}`:
`{"action": "undo:"}` would undo inside the step's own undo group, which NSUndoManager rejects.

Snapshots are composited by the app itself (the text view rendered as vector PDF, then the
toolbar, fade and the title bar's contents on top): vibrancy blur is not reproduced, and sheets are
captured with `"window": "sheet"`.

## Steps

| Step | Does |
| --- | --- |
| `{"open": "path"}` | Opens a copy of a file (relative to `--ui-root`, the cwd or the script). `"folder": true` also copies everything beside it (the images a document refers to by relative path). |
| `{"openGenerated": {"from": "path", "minLength": 1000000}}` | Opens `from` repeated to at least that many UTF-16 units. |
| `{"new": true}`, `{"load": "text"}` | New untitled document; replace its text. |
| `{"makeFile": {"name": "x.md", "text": "ab", "repeat": 3, "prefix": "", "suffix": "", "bom": true, "lineEndings": "mixed", "readOnly": true}}` | Writes a file into `made/` in the output directory and opens it (a copy, as `open` does): inputs too big or odd to keep in the repository. `"binary": n` writes n bytes of noise instead; `"expectOpen": false` passes when the app refuses it with an error; `"open": false` only writes it. |
| `{"modifyOnDisk": {"append": "text", "coordinated": true}}` | Another program changes the open document's file (`replace` replaces it), through a file coordinator or not. |
| `{"saveAs": "name.md"}` | File > Save of an untitled document, the panel answered with `work/name.md` in the output directory. |
| `{"memory": "label", "maxGrowthMB": 120, "maxPrintRenderers": 0}` | Logs the memory footprint (the first is the baseline) and the live print renderers; fails above the limits. |
| `{"type": "text", "interval": 0.05}` | Key events (`\n` Return, `\t` Tab, `⇤` Shift-Tab). |
| `{"key": {"chars": "b", "mods": ["cmd"]}}` | One key event; Command keys go through the main menu. |
| `{"select": [loc, len]}`, `{"selectText": "needle", "offset": n, "length": n}` | Selection. |
| `{"action": "toggleStrong:", "tag": 2}` | `NSApp.sendAction` (tag for heading level, alignment). An action that edits runs as one undo group; `"edits": false` (view toggles such as `toggleFocusMode:`, and `{"command": ...}` moves) sends it plain, because a closed empty undo group marks the document edited. |
| `{"command": "insertNewline:"}` | `doCommand(by:)` on the text view; logs the selection and the caret's x afterwards, and fails if it is not `"expectSelection": [loc, len]`. |
| `{"setting": {"theme": "dark", "fontChoice": "iaDuo", "fontSize": 20, "lineWidth": 60, "centreFocusedLine": true, "chromeReturnsAfterPause": true, ...}}` | Settings. |
| `{"appearance": "dark"}` | App appearance (`light`, `dark`, `system`), for the System theme. |
| `{"wait": 0.5}`, `{"waitStyled": 20}` | Time; styling caught up. |
| `{"snapshot": "name", "window": "settings"}` | PNG of the document window, Settings or the attached sheet. `"bitmap": true` renders the text view as it is drawn on screen (selection highlight and caret included; the default vector rendering leaves them out). |
| `{"resize": [w, h]}`, `{"fullscreen": true}`, `{"scroll": "end"}` | Window. Full screen is skipped when the app is not active. `scroll` also takes a y offset (negative: above the text); it logs where the editor stopped, and `"notAbove": y` fails if it went above `y`. |
| `{"switchTo": 0}`, `{"settingsWindow": "show"}`, `{"sheet": "end"}` | Windows (`new` opens an untitled document in a window of its own; `switchTo` brings the i-th open document's window forward). `"sheet": "end"` answers the attached sheet with its second button (Cancel), `"sheet": "accept"` with its first (Insert, OK). |
| `{"pointer": "moved"}` | What a mouse move does to the auto-hiding chrome. |
| `{"undo": true}`, `{"redo": true}` | Document undo manager. |
| `{"clickCheckbox": 0}`, `{"cmdClickLink": "needle"}`, `{"dropFile": "path"}` | The `[ ]` of the n-th task item is clicked; the link under the needle is Cmd-clicked (nothing is really opened: the URL is recorded for `linkOpened`); a file is dropped at the caret (`out:work/x.png`: a file in the output directory). |
| `{"codeBadge": {"click": "needle", "choose": "Python"}}` | Clicks the language badge of the block holding the text (the text view's own hit test; fails when the block has no badge or the caret is hiding it) and takes the menu it opens instead of tracking the mouse; `choose` picks an item of it by title or token, through the item's own action (one undo step). With `"real": true` the click is a real one (mouse events posted to the queue, through the window's hit-testing and `mouseDown`), the menu really pops up and tracks, and once open it is closed through its own API (`cancelTracking`) before `choose` is taken, or `keys` (`down`, `up`, `left`, `right`, `return`, `escape`) are posted to it one at a time as key events (its own keyboard navigation; the highlighted item after each is logged, `expectHighlighted` checks the first ones); with neither, the caret must not have moved. A plain `click` on a badge that is showing is refused (it would leave a menu tracking). Asserted with `{"assert": {"code": {...}}}`: `badges` (the ones showing, in order), `badgesIgnoringCaret`, `noBadge` (a text in a block without one), `badgeAtTopRightOf`, `badgeHiddenByCaret`, `caretClearOfBadge`, `codeColours` (`needle`, `role`: a role, `focusDim`, `code`, `text` or `markup`; the colour drawn: the overlay's over the stored one, and for text outside the window the overlay paints, the layer's), `temporaryColour` (`is`: `focusDim`, `none` or a role: the overlay's colour), `codeMenu` (`first`, `last`, `checked`, `commonCount`, `allGroups`), `accessibleBadges` and `pressAccessibleBadge`. |
| `{"httpServe": "dir", "port": 8765}` | Serves a folder on `http://127.0.0.1:port/` from inside the app (remote pictures without the internet). |
| `{"copyFile": {"from": "path", "to": "work/x.png"}}` | Replaces a file beside the opened copy (`to` is relative to the output directory). |
| `{"pasteImage": "path.png", "wait": 3}` | Pastes PNG data from a private pasteboard (Edit > Paste's image path); waits for it to be written, or for the save panel. |
| `{"dumpLayout": "needle"}` | Logs line fragments and glyph positions (`N` null, `C` control) of the paragraph holding the needle. |
| `{"measureTyping": {"count": 150, "interval": 0.06, "maxMs": 10}}` | Main-thread time per keystroke and the longest run-loop gap. |
| `{"measureCaret": {"count": 200, "stride": 97}}` | Main-thread time per caret move (the selection change and the query it triggers). |
| `{"measureDrift": {"rounds": 300, "keys": 20, "moves": 4, "factor": 2}}` | A long session at random: each round jumps the caret to scattered places and types at the last one. Records per key and per jump the main-thread cost, with the size of everything the session keeps (concealment, overlay runs, attribute runs), the analysis queue's time per edit and a fixed-arithmetic calibration of the machine; the last tenth of the rounds must stay within `factor` (plus `slackMs`) of the first tenth, judged against how much slower the calibration got. `experiment: {"round": n, "do": "removeUndo"\|"invalidateLayout"\|"invalidateGlyphs"\|"removeTemporary"}` applies one remedy mid-run. See `drift.json`. |
| `{"measureKeys": {"count": 200, "command": "moveRight:"}}` | Main-thread time per arrow-key press through the key bindings, drawing included. |
| `{"measureJump": {"count": 20}}` | Time to scroll to a far place and lay out and draw the screenful there (a scroll-smoothness proxy). |
| `{"focus": {"on": true, "scope": "paragraph"}}` | Focus mode for this window (`on`: through View > Focus Mode's action) and the scope setting (`sentence`, `paragraph`); asks for the focus range at once. |
| `{"syntax": {"on": true, "classes": ["noun", "verb"]}}`, `{"waitSyntax": 30}` | Syntax highlighting for this window (View > Syntax Highlight's action), and the classes (a setting: the five names, the rest are switched off); waits until tagging has settled. |
| `{"setPasteboard": "text"}`, `{"copyOrCut": "copy"}` | The window's private pasteboard (never the user's): what `{"action": "paste:"}`, `pasteAsAI:`, `pasteAsReference:`, `pasteAsMe:` read; copy or cut the selection onto it (with the authorship marks). `markAsAI:`, `markAsReference:`, `markAsMe:`, `markAsNoAuthor:` act on the selection. |
| `{"authorshipDisplay": true}`, `{"action": "toggleAuthorshipDisplay:", "edits": false}` | Shows or hides the colouring of borrowed text in this window. |
| `{"save": true}`, `{"reopen": true}` | Writes the (scratch) document to its file through the save path; closes it and opens the file afresh. |
| `{"undoUntilLacks": "needle"}`, `{"undoUntilContains": "needle"}`, `{"redoUntilContains": "needle"}` | Undo or redo until the text has (or has lost) the needle: typing through key events is several undo steps here (each key is its own group). |
| `{"authorshipDecision": "keep"\|"discard"}` | Shows the keep-or-discard sheet (a file whose marks may be misplaced) and answers it through its buttons. |
| `{"frontDocument": true}` | The script's document becomes the one now in front (one the app opened itself, such as Help > Markdown Help). |
| `{"close": true}` | Closes the document and checks that it, its window controller, session and coordinator are freed. With `UI_SCRIPT_LEAK_PAUSE=60` in the environment, whatever outlived it is logged with its address and the script waits that long, for `leaks --traceTree=<address> <pid>`. |
| `{"controlLeakProbe": true}` | The same check for a plain AppKit window (AppKit keeps closed windows for a while). |
| `{"markEvery": {"stride": 300, "length": 100, "as": "ai"}}` | Marks `length` characters every `stride` (every third as Reference): thousands of authorship runs at once, for timing. Not undoable. |
| `{"soak": {"steps": 300, "seed": 1, "fileEvery": 10, "toggles": true}}` | Random steps of every kind with the checks described under `soak.json` after each; fails on the first ten problems and records timings per kind of step. `toggles: false` leaves modes, themes and switches alone. |
| `{"measureSave": true}` | Saves through NSDocument and records the total time, the longest main-thread gap meanwhile, the file size and whether the write ran off the main thread. |
| `{"doubleClickTitlebar": {"x": 0.5, "expect": "any"}}` | A double-click on the title bar, as one `leftMouseDown` with a click count of two sent to the window (a first click alone would start AppKit's drag loop and wait for a button that never comes). Logs the view the click lands on, and passes when the window did what System Settings' "Double-click a window's title bar to" says (`AppleActionOnDoubleClick`: zoom by default, minimize, or nothing): the frame changed, the window is minimized (and is brought back), or nothing moved. `x` is a fraction of the width, or points when above 1. |
| `{"liveResize": {"steps": [[-24, 0], [0, -18]], "maxOffset": 0.5}}` | A live resize through AppKit's own resize loop: a mouse-down on the window's bottom-right corner, then one drag per step (fed by a timer inside the loop; queued at once they would be coalesced) and the mouse-up. Records the caret line's distance from the middle after each frame, at the mouse-up and once settled, any move of the editor afterwards, and the distance from where a keystroke would put it; fails above `maxOffset`, on any slide or late move. `"centred": false` (Split, where nothing is centred): the distances are only logged, and the step fails on a slide, on room made for centring or on a late move. |
| `{"click": {"needle": "word", "offset": 1, "count": 1, "mods": ["cmd"]}}`, `{"drag": {"from": "a", "to": "b"}}`, `{"dividerDrag": 0.4}` | Real mouse events posted to the app's event queue, so they go through `NSApplication.sendEvent`, `NSWindow.sendEvent` (hit-testing, the first-responder change) and the text view's own tracking loop, as the window server's would; the window is made key first (a click on a background app's window only brings it forward). `click` goes to a character of the text (left quarter: the caret goes before it), or `"at"`: `badge` (`needle`: the block's badge; `side`: `left`, `right`, `below`, `centre`, `gap` points from the pill; `ignoringCaret`: where the pill is even while the caret hides it), `checkbox` (`index`), `preview`, `sidebar` (`row`), `search`, `toolbar`, `window` (`x`, `y`: fractions, or points from the bottom left; `expectCaret`), `titlebar`, `title` (the app's own title, `x` a fraction across its name); `count` makes a double or triple click. Each logs the view the window hit-tests at the point (`hit`, `hitIn`: `text`, `toolbar`, `preview`, `sidebar`, `divider`, `titlebar`, `other`), the first responder, the selection and whether the window was key. A plain click on text must leave the caret before the clicked character; also `expectSelection`, `expectSelectedText`, `expectResponder` (`text`, `preview`, `sidebar`), `expectHit`, `expectHitIn`, `expectWindowAction` (a title-bar double-click did what System Settings says), `expectRename` (a window of AppKit's came up by the title, the rename popover, and the window did not zoom; it is dismissed with Escape). `"probe": true` only logs where the click would land, and whether the view there lets a press move the window (`canMoveWindow`, checked by `expectCanMoveWindow`; AppKit's own title buttons, the document icon and "Edited", are exempt): the condition AppKit puts on a title-bar drag, which the window server then performs with the real pointer, so posted drag events cannot move a window and a drag of the title bar is checked this way. `drag` presses on one character and releases on another; `dividerDrag` drags the split divider to a share of the width. |
| `{"contextMenu": {"needle": "word", "offset": 1, "has": [...], "lacks": [...], "choose": "Mark This Passage As > AI", "expectSelection": [loc, len]}}` | A right-click on a character. The real `rightMouseDown` event is built for the window's point and hit-tested, and handed to the text view's `menu(for:)`; it is not posted, because AppKit's tracking of a popped-up menu blocks until a button is released that the harness cannot press. The items are validated, `has` and `lacks` check top-level titles, and `choose` (titles joined by `>`) performs the item's own action. The assertion `selectionEmpty` (true or false) checks whether the selection is a caret. |
| `{"scrollWheel": {"dy": -260, "wait": 0.1}}` | A pixel-unit scroll-wheel event delivered to the editor's scroll view (a user scroll for focus mode's centring). |
| `{"remember": "name"}` | Stores the caret line's position in the window, the editor's scroll origin and the title bar's height, for the assertions `caretUnmoved`, `originUnchanged`, `originChanged`, `titlebarHeightSameAs`. |
| `{"observeScroll": {"do": "toggleFocusMode:", "type": "\n", "seconds": 0.8, "expectFrames": 5, "expectDuration": [0.15, 0.5], "monotonic": true}}` | Performs an action (or types) and records every bounds change of the editor's clip view meanwhile: frames, duration, longest and mean gap between frames, travel, whether it only moved one way, and the share of the travel done at a quarter, half and three quarters of the time (an ease-in-out slide: slow, 0.5, fast). |
| `{"history": {...}}` | The history panel and the store behind it (see `history.json`). One verb per step: `show` (View > Show History's action, or the header's segment when the column is on the outline; `show: false` hides the column when it shows History), `waitVersions` (the store holds that many versions of the document), `select` (the i-th version, newest first), `restore`, `copy` (to a pasteboard of the script's own), `waitDiff`, `message` (a snapshot with a message), `key`. The store is a folder beside the output (`history/`), never the user's. |

| `{"notes": {...}}` | Notes mode (see below). ## Relaunching, quitting, the session record

A script that needs the app to end and start again uses `{"relaunch": {"suppress": false, "expectDialog": true}}`: the app
quits through its normal path (`NSApp.terminate`, so the question "Quit Markdown?" is asked, and answered Quit through its
API, with its checkbox ticked for `suppress`; `expectDialog` fails the step if the question was, or was not, asked), leaves
`relaunch.json` in the output folder, and `ui-script.sh` starts it again with `--ui-resume`, the same defaults suite
(`--ui-defaults`, `UI_DEFAULTS=`; it is emptied only by the first launch), history folder and session record
(`--ui-record`, always `<out>/session.json`, used only by a script with a `relaunch` or `session` step), going on from the
next step with the log carried over. `{"quit": {"answer": "cancel", "suppress": true, "expectDialog": true}}` is ⌘Q: Cancel
goes on, Quit ends the script. `{"session": {"snapshot": "name"}}` notes the windows (kept across relaunches);
`{"session": {"write": true}}` writes the record; `{"session": {"deleteFile": "name.md"}}` removes the script's copy of a
file. Assertions under `"session"`: `windows`, `files` (front to back), `front`, `untitledText`, `restored`, `skipped`,
`recordWindows`, `askBeforeQuitting`, `reopenAtLaunch`, `quitDialogs`, `lastQuitDialog`, `settingsSwitches`, `sameAs` (the
windows now equal the snapshot: files, frames, modes, column, sidebar state, caret, scroll, key), `window` (one window's
layout, mode, focus, notes, selection, sort, column, caret). The settings `reopenAtLaunch` and `askBeforeQuitting` are scriptable.
